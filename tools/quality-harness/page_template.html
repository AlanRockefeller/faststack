The score counts how often you picked version A, version B, “different but neither better”, and “the same” — A and B are named under each comparison. Which one appeared as image 1 was reshuffled every trial, so a preference only counts if it keeps landing on the same algorithm: p is a two-sided binomial test over the trials where you did pick a side, since neither version was predicted to win. “Different, neither better” is a result, not a missing answer — it says the change is visible but not a loss, which is exactly the finding that lets a cheaper path ship for thumbnails and rapid navigation while the settled view keeps the careful one. Every verdict is tied to that viewing condition and says nothing about a different size or zoom. ABX rows score correct identifications of X instead. Trials accumulate across sessions and across modes.

Magnification is flagged per row because it changes what a verdict means. A difference you can only resolve at 3× or 4× is one FastStack's own display will never show you — so a “prefers A (magnified)” row is grounds for looking again at 1×, not for keeping the slower path.
